# Windows laptop physical-device test kit

The user has an iPad and Pencil beside a separate Windows laptop. That laptop can use RDP, but its USB devices are not physically attached to this development host. Build a transferable source/test kit so the experiments run at the laptop and iPad, and return one result archive for review.

Use the existing checkout and Swift Playground route. A dedicated playground uses the current canvas/storage sources and an isolated test note, generates 10,000 strokes, runs repeatable camera movement, samples display-link callback intervals, app physical footprint, battery/thermal/power state, and verifies saved records after reopening the store. Results are written incrementally and exportable as JSON. Normal student notes are untouched. The default automated workload takes 90 seconds; an optional 10-minute run records battery levels while unplugged. Charging/unknown battery state makes battery drain inconclusive. Display-link cadence is not photon latency or independently measured display FPS.

The Windows runner uses pinned pymobiledevice3 11.61.2 for USB preflight, optional DVT display FPS/process memory capture, source transfer to Swift Playgrounds Documents, and collection of lab reports. CLI errors, missing device/app/developer support, multiple devices and empty streams remain visible in the result archive. Do not auto-select among multiple devices, kill arbitrary apps or copy personal app containers. Read only this kit's lab report directory. The only writable source-transfer destination is the fixed ReedleDeviceLab-Source.zip file within Swift Playgrounds Documents.

The launcher downloads a pinned uv binary with embedded SHA-256, provisions Python 3.12 and locked dependencies locally, and runs without changing global execution policy or installing a USB driver. Apple Devices / USB trust and iPad source opening remain explicit initial setup. A signed IPA is optional; never label source as an installable binary. No BAZE or Apple account credential is included or requested by the kit.

Pencil physical response and actual window-management gestures require one operator session. Provide explicit reasons and a short checklist. If quantitative contact-to-ink latency is desired, accept high-speed video frame indices and frame rate and report resolution limits; do not replace it with app callback latency. Keep AET-49 open until actual device evidence is returned and reviewed.

Approaches considered: forwarding USB through RDP would require laptop configuration and fragile cross-host networking; requiring a separately signed XCTest runner would introduce unavailable signing credentials. Running the test source on iPad and collecting through the local Windows laptop uses the equipment the user actually has. These are implementation choices, not additional user approvals.

Verification: meaningful offline tests cover command selection, device ambiguity, missing/failed measurements, simulator rejection, charging-battery rejection, result archive integrity and path safety. One grouped native check compiles/runs the new lab controller and metrics. Do not repeat the already passed live-model batch for test-kit-only code.
